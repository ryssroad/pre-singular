# PULSE — локальная память жизни

> Статус: **draft** · Версия 0.1 · 2026-08-02
> Автор линзы: One (системный аналитик редакции)

PULSE — это персональная система памяти, которая работает на устройстве
пользователя, собирает контекст жизни через набор узких сенсоров и хранит из
него только тонкий след — эпизоды, а не эфир.

Главный проектный вопрос не «что система видит», а **что собранному разрешено
стать**. Любая система такого класса деградирует в домашний паноптикум по одной
и той же траектории: сбор, хранение, понимание и действие оказываются одним
процессом с одним набором прав. Дальше всё определяется добросовестностью кода,
а добросовестность кода — не архитектура.

## Основное правило

> **Сбор ≠ хранение. Хранение ≠ понимание. Понимание ≠ действие.**

Эти четыре слоя MUST быть разведены физически: отдельные процессы, отдельные
хранилища, отдельные права. Граница, которая не является границей процесса, —
не граница, а обещание.

## Четыре слоя

| Слой | Что делает | Живёт в | Видит слой ниже | Видит слой выше |
|---|---|---|---|---|
| **L0 collect** | сенсоры порождают наблюдения | отдельный процесс на сенсор | — | нет |
| **L1 retain** | буфер наблюдений с TTL | RAM, ring buffer | L0 | нет |
| **L2 understand** | нормализация → выводы → эпизоды | локальная БД | L1 | нет |
| **L3 act** | предложения и (по подтверждению) действия | процесс агента | только L2-эпизоды | — |

Правило видимости: **каждый слой читает только соседний снизу и никогда не
читает через голову.** Слой действия не имеет доступа к сырью ни при каких
настройках — не потому, что запрещено, а потому, что канала не существует.

## Как это выглядит в жизни

Сенсор пишет короткое событие:

```
ble.known-devices: airpods_pro present
```

Локальный нормализатор превращает это (вместе с соседними наблюдениями) в вывод:

```
home.presence: user_likely_home (0.86)
```

Episode Builder решает, стоит ли вообще связывать это с остальным. Сырьё к тому
моменту уже удалено — оно жило минуты. В долговременную память попадает не
Bluetooth-эфир, а одна строка:

```
04:09 · дома · сад · музыка · рабочий контекст завершён
```

## Что PULSE не делает

Явные non-goals. Они здесь, чтобы их нельзя было тихо пересмотреть.

- **Не облако.** Никакой синхронизации «для удобства». Сетевая граница живёт в
  супервизоре, а не во флаге внутри приложения.
- **Не многопользовательская система.** Одно устройство, один владелец.
- **Не доказательство.** Эпизоды лоссовые по построению. Вывод PULSE MUST NOT
  подаваться как запись факта для третьей стороны — ни как алиби, ни как улика,
  ни как отчёт работодателю.
- **Не инструмент наблюдения за другими.** Сенсоры видят и людей, которые
  ничего не подписывали. Архитектура, которая защищает только владельца, — это
  не приватность, это личное преимущество.

## Порядок сборки

Милстоуны идут так, чтобы ограничения появились раньше возможностей. Обратный
порядок — обычный способ получить паноптикум с извинениями.

- **M0 — скелет запрета.** Супервизор, режимы, «Forget the last hour», журнал.
  Ноль сенсоров. Система, которая ничего не умеет, но умеет останавливаться.
- **M1 — три тупых сенсора.** `net.ssid-class`, `ble.known-devices`,
  `media.now-playing`. L1-буфер с TTL. Никакого L2.
- **M2 — понимание.** Декларативный нормализатор, Episode Builder с бюджетом,
  лестница хранения целиком.
- **M3 — действие.** Слой предложений. Ни одной capability из списка
  подтверждаемых до тех пор, пока M0 не проверен вручную на живой системе.

## Цена

Эта архитектура делает систему заметно тупее той, что могла бы получиться из
одного всевидящего демона. Она хуже помнит, чаще ошибается в выводах и не умеет
объяснить вчерашний вывод по существу — потому что сырья уже нет. Это
сознательный размен: точность на забывание. Он назван здесь один раз, чтобы
дальше по тексту его не пришлось изобретать заново как недостаток.
