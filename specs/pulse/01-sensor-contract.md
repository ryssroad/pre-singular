# 01 — Контракт сенсора

> Статус: **draft** · Слой L0/L1

## Что такое сенсор

Сенсор — это **отдельный процесс с одним источником, одной схемой вывода и без
права на что-либо ещё**. Не библиотека внутри агента. Не плагин. Процесс.

Правильная архитектура здесь — не десяток всевидящих демонов, а набор тупых
локальных сенсоров с очень узкими правами. Один видит только название текущего
трека. Другой — только факт, что знакомый BLE-девайс рядом. Третий — только
смену Wi-Fi. Общего доступа ко всей жизни нет ни у кого.

## Требования к процессу

Каждый сенсор MUST:

- запускаться под собственным uid и собственным профилем песочницы;
- иметь **ровно один** OS-permission, объявленный в манифесте;
- писать только в свой outbox-сокет; никакой другой записи на диск;
- не иметь сетевого доступа (enforced супервизором, не самодисциплиной);
- не читать вывод других сенсоров;
- быть push-only: сенсор нельзя опросить, он только отдаёт.

Сенсор MUST NOT иметь возможности:

- узнать текущий режим системы;
- узнать, что происходит с его событиями дальше;
- получить обратную связь от слоя понимания или действия.

Последний пункт важнее, чем кажется. Сенсор без обратной связи не может быть
адаптирован под то, что «интересно» модели. Канала для такой адаптации просто
нет.

## Редукция происходит внутри сенсора

Это несущее решение всей схемы.

**Сенсор не отдаёт сырьё. Он отдаёт уже сведённое значение.**

BLE-демон внутри себя знает MAC-адреса, RSSI, вендоров и всех соседей в радиусе.
Наружу он может сказать только алиас из подтверждённого пользователем списка и
одно из двух состояний. Bluetooth-эфир не покидает процесс сенсора никогда —
не потому, что дальше его кто-то отфильтрует, а потому, что схема вывода не
способна его выразить.

Из этого следует правило про чужих:

> Неизвестное устройство MUST NOT порождать событие вообще —
> в том числе событие вида «рядом неизвестное устройство».

Гости ничего не подписывали. Счётчик неопознанных устройств — это уже наблюдение
за другими людьми, просто с плохим разрешением.

## Манифест

Манифест объявляется при установке сенсора, показывается пользователю целиком и
пиннится по хешу.

```yaml
id: ble.known-devices
version: 1
title: "Знакомые устройства рядом"

reads: bluetooth.le.scan        # ровно один OS-permission

emits:
  - type: proximity.known_device
    fields:
      device_alias: {kind: enum, source: user_allowlist}
      state:        {kind: enum, values: [present, absent]}

budget:
  events_per_hour: 12           # жёсткий потолок, enforced
  time_resolution: 1m           # округление меток времени
  text_fields: 0                # см. «Полоса и текст»

network: none
retention: {layer: L1, ttl: 15m}
```

Правила манифеста:

- **Изменённый манифест — это новый сенсор.** Любое изменение `emits`, `budget`
  или `reads` сбрасывает согласие; сенсор останавливается и требует повторного
  подтверждения. Версия без повторного согласия MUST NOT запускаться.
- `budget.events_per_hour` enforced супервизором. Превышение — не лог, а
  остановка сенсора с записью в журнал.
- `retention.ttl` может быть только сокращён ниже по конвейеру. Продлить его
  нельзя ни одним слоем.

## Полоса и текст

Поле произвольного текста — это скрытый канал. Сенсор с одним свободным
строковым полем может вынести наружу что угодно, включая всё то, ради
недопущения чего написана остальная спека.

Поэтому типы полей ограничены: `enum`, `bool`, малые `int`, огрублённое время.

Текст разрешён, но по отдельным правилам. Сенсор вроде `media.now-playing`
физически не может работать без строки — название трека и есть его смысл.
Такие сенсоры объявляют `text_fields: N` и получают статус **high-entropy**:

- содержимое текстовых полей MUST показываться в утреннем журнале дословно;
- TTL для high-entropy сенсоров MUST быть ≤ 15 минут на L1;
- текст MUST NOT попадать в L2 и L3 в исходном виде — только как производный
  признак (`music: true`, жанр, факт смены трека).

## Схема наблюдения

Единица вывода сенсора — observation. Формат фиксированный:

```json
{
  "v": 1,
  "sensor": "ble.known-devices",
  "type": "proximity.known_device",
  "t": "2026-08-02T04:09:00+03:00",
  "t_res": "1m",
  "fields": {"device_alias": "airpods_pro", "state": "present"},
  "confidence": 1.0,
  "ttl": "15m"
}
```

Замечания по полям:

- **Нет идентификатора устройства и пользователя.** Система однопользовательская
  и локальная; идентификатор здесь — только будущая точка утечки.
- `t_res` объявляется явно. Огрубление времени — это средство приватности, и оно
  должно быть видимым числом, а не побочным эффектом реализации.
- `confidence` заполняет сенсор, если сам источник вероятностный. Слой понимания
  не имеет права поднимать это значение.
- Наблюдение, не проходящее валидацию по манифесту, отбрасывается, а сенсор
  останавливается. Мягкой деградации здесь нет: сенсор, который врёт про свою
  схему, сломан целиком.

## Стартовый набор

Минимальный набор M1. Все три — низкоэнтропийные, все три полезны по отдельности.

| id | reads | emits | budget/h | ttl |
|---|---|---|---|---|
| `net.ssid-class` | `wifi.current_network` | `network.ssid_class {home, work, mobile, other}` | 20 | 15m |
| `ble.known-devices` | `bluetooth.le.scan` | `proximity.known_device {alias, present/absent}` | 12 | 15m |
| `media.now-playing` | `media.playback_state` | `media.track {title(text), state}` | 60 | 15m |

`net.ssid-class` не отдаёт SSID — только класс сети из пользовательской
разметки. Имя сети это ещё один идентификатор места, и он не нужен ни одному
выводу выше.

## Сенсоры высокой чувствительности

Голос, камера, содержимое сообщений, терминал, точная геолокация — отдельный
класс. Он не является продолжением этой таблицы вниз; это другой режим работы
системы.

- default **off**, всегда;
- включение только физическим действием человека; агент MUST NOT иметь канала,
  которым он мог бы попросить или инициировать включение;
- видимый индикатор на уровне ОС на всё время работы — не индикатор внутри
  приложения;
- аппаратный kill switch там, где железо это позволяет;
- включение даёт **сессию, а не состояние**: не более 60 минут, потом выключение
  без напоминаний и без продления одной кнопкой;
- каждая сессия попадает в утренний журнал: что, когда, сколько минут.

## Цена

Тупые сенсоры дают заметно худшее качество выводов, чем один демон с полным
доступом. Алиасы вместо адресов — это ручная работа пользователя при настройке.
Запрет на события о неизвестных устройствах означает, что система не заметит
ничего нового в окружении, пока человек сам это новое не назовёт. Это
осознанный размен: система хуже понимает мир, зато не ведёт учёт чужих людей.
