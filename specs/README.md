# specs/ — проектные документы

Третий мир репозитория, рядом с `dossiers/` (сырьё) и `publish/` (готовое к постингу).

`specs/` — это то, из чего можно писать код. Не эссе, не досье, не заметка.
Документ живёт здесь, если по нему можно поставить задачу инженеру и он не будет
догадываться о деталях.

## Правила

- **Один спек — одна система.** Подпапка на систему: `specs/<system>/`.
- **Нормативный язык.** MUST / SHOULD / MAY (RFC 2119) — по-английски, чтобы
  требование нельзя было спутать с пожеланием. Прочее — по-русски.
- **Идентификаторы — английские.** Имена сенсоров, событий, capability, режимов
  пишутся так, как они будут выглядеть в коде.
- **Компромиссы называются вслух.** Если решение что-то ломает — в тексте есть
  абзац «Цена». Спека без цены — маркетинг.
- **Статус в шапке.** `draft` → `agreed` → `implemented`. Без статуса документ
  считается черновиком.

## Отношение к `publish/`

Спека может стать источником для публикации. Тогда в тексте в очереди стоит
`source:` с указанием на файл спеки — так же, как тексты ссылаются на брифы досье.
Обратное неверно: эссе не является спецификацией, даже если описывает архитектуру.
